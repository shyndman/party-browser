  <name>Task 1: Create selector discovery workflow guide</name>
  <files>.planning/guides/selector-discovery-workflow.md</files>
  <action>
    Create a comprehensive guide at `.planning/guides/selector-discovery-workflow.md` documenting the LLM-guided selector discovery workflow.
    
    The guide must include:
    
    **1. Overview**
    - What is selector discovery
    - Why LLM-guided approach
    - Expected outcome (selector artifact)
    
    **2. Prerequisites**
    - Browser MCP server running
    - Browser extension installed and connected
    - Target URL ready
    
    **3. The 5-Step Workflow**
    
    **Step 1: Page Exploration**
    - Tools: browser_navigate, browser_snapshot, browser_screenshot
    - Goal: Understand page structure and identify target elements
    - Example prompt chain:
      ```
      1. Navigate to https://example.com/products
      2. Take a screenshot to see the visual layout
      3. Get a snapshot to see the accessibility tree
      ```
    
    **Step 2: Target Identification**
    - Tools: browser_evaluate for inspection
    - Goal: Identify what elements to extract and their semantic meaning
    - Example evaluation scripts:
      - Count elements: `document.querySelectorAll('.product').length`
      - Check for shadow DOM: `!!document.querySelector('*').shadowRoot`
      - Find semantic landmarks: `document.querySelectorAll('[role=main], [role=article]').length`
    
    **Step 3: Candidate Generation**
    - LLM analyzes snapshot + screenshot to generate selector candidates
    - Priority order for selectors:
      1. Semantic (role, aria-label, aria-labelledby)
      2. Test IDs (data-testid, data-test-id)
      3. Stable attributes (id, name, type)
      4. Structural (CSS path, nth-child)
    - Output format: JSON with candidates array
    
    **Step 4: Validation**
    - Tools: browser_evaluate to test selectors
    - Goal: Verify selectors match expected elements
    - Example validation:
      ```javascript
      // Test if selector finds elements
      document.querySelectorAll('[data-testid="price"]').length
      
      // Verify element content
      document.querySelector('.product-title')?.textContent
      ```
    
    **Step 5: Interaction Verification** (if needed)
    - Tools: browser_click, browser_type, browser_select_option
    - Goal: Verify interactive elements work for data extraction
    - Example: Click "Load More" and verify new content appears
    
    **4. Example: Complete Discovery Session**
    Provide a complete example showing the full workflow on a hypothetical e-commerce site.
    
    **5. Selector Artifact Format**
    Document the expected output format for discovered selectors:
    ```json
    {
      "url": "https://example.com/products",
      "discovered_at": "2026-02-09T12:00:00Z",
      "selectors": [
        {
          "name": "product_title",
          "selector": "[data-testid='product-title']",
          "type": "css",
          "description": "Product name/title",
          "validated": true,
          "priority": 1
        }
      ]
    }
    ```
    
    **6. Best Practices**
    - Prefer semantic selectors over structural ones
    - Validate selectors on multiple page variations
    - Document why each selector was chosen
    - Test interactions before finalizing
    
    **7. Troubleshooting**
    - Selector returns wrong element → use more specific criteria
    - Selector breaks on page update → prefer data-* attributes
    - Element not found → check for lazy loading, try waiting
  </action>
