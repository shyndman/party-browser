<objective>
Implement selector artifact export for handoff to procedural scraping.

Purpose: Enable users to package discovered selectors into a machine-readable format that can be executed by downstream scraping systems without LLM involvement. This closes the loop between LLM-guided discovery and repeatable execution.

Output:
- TypeScript types defining the selector artifact format
- MCP tool `browser_export_selectors` that generates artifacts
- Artifact includes: selector definitions, session metadata, network/console summary
- JSON format inspired by Chrome DevTools Recorder (human-readable, tool-agnostic)
</objective>

<task type="auto">
  <name>Task 1: Define selector artifact TypeScript types</name>
  <files>
    src/types/artifact.ts
  </files>
  <action>
    Create src/types/artifact.ts with type definitions for the selector artifact format:

    1. SelectorDefinition type:
       - type: 'css' | 'xpath' | 'text' | 'ref'
       - value: string (the actual selector)
       - multiple?: boolean (extract single or multiple elements)
       - attribute?: string (extract attribute instead of text)
       - fields?: Record<string, SelectorDefinition> (for structured extraction)

    2. SelectorStep type (actions in the workflow):
       - type: 'navigate' | 'click' | 'type' | 'select' | 'wait' | 'extract' | 'screenshot'
       - For navigate: url: string
       - For click: selectors: SelectorDefinition[]
       - For type: selectors: SelectorDefinition[], value: string
       - For select: selectors: SelectorDefinition[], option: string
       - For wait: mode: 'time' | 'selector', value: number | string
       - For extract: name: string, selectors: SelectorDefinition[]
       - For screenshot: (no extra fields)
       - description?: string (human-readable explanation)

    3. SelectorArtifact type (the root export format):
       - version: '1.0'
       - title: string
       - createdAt: string (ISO timestamp)
       - sessionId: string
       - initialUrl: string
       - steps: SelectorStep[]
       - metadata: {
           networkRequestCount: number,
           consoleErrorCount: number,
           consoleWarnCount: number,
           sessionDuration: number (ms)
         }

    4. Export helper types:
       - ExportOptions: { name, includeMetadata, includeConsole, includeNetwork }
       - ExportResult: { artifact, json, filename }

    PATTERNS FROM RESEARCH:
    - Follow Chrome DevTools Recorder JSON format for compatibility
    - Keep selectors as arrays to support fallback strategies
    - Include session correlation metadata for debugging
    - Structure extraction with named fields for tabular data
  </action>
  <verify>
    Run npm run build
    Verify TypeScript compiles without type errors
    Check that types match the format described in 03-RESEARCH.md
  </verify>
  <done>
    - src/types/artifact.ts exists with all type definitions
    - Types are exported and importable
    - TypeScript build passes
    - Format aligns with Chrome DevTools Recorder pattern
  </done>
