<objective>
Implement session-scoped network and console capture infrastructure.

Purpose: Enable users to inspect browser internals during discovery sessions for debugging selector and timing issues. This visibility is critical for diagnosing why selectors fail or pages behave unexpectedly.

Output: 
- Per-session network request capture using Firefox webRequest API
- Console message capture via content script method override with bounded ring buffer
- Two new MCP tools: `browser_network_requests` and `browser_console_messages`
</objective>

<task type="auto">
  <name>Task 1: Add webRequest permissions and per-session network capture</name>
  <files>
    extension/manifest.json
    extension/background.js
  </files>
  <action>
    Update manifest.json to add "webRequest" permission for network capture.

    In background.js, implement per-session network capture:
    1. Add sessionNetworkLogs Map to store request data per session (key: sessionTabId, value: array of request objects)
    2. Create startNetworkCapture(tabId) function that:
       - Registers browser.webRequest.onBeforeRequest listener with filter {urls: ["<all_urls>"], tabId}
       - Stores request data: requestId, url, method, type, timeStamp, requestBody
       - Registers browser.webRequest.onCompleted to capture statusCode and responseHeaders
       - Registers browser.webRequest.onErrorOccurred to capture error details
    3. Start capture when sessionTabId is set (in handleNavigate after tab creation)
    4. Stop capture and clear logs when session is lost (tab close, transport drop, kill switch)
    5. Add handleGetNetworkRequests command to retrieve logs (with optional filter by type/urlPattern)
    6. Implement ring buffer pattern: keep last 1000 requests per session, discard older ones

    PITFALLS TO AVOID:
    - MUST filter by tabId to prevent cross-session leakage
    - MUST clear logs on session_lost to prevent stale data
    - MUST handle response body capture carefully (skip bodies >1MB for performance)
    - MUST NOT capture all traffic without filtering (exclude analytics/CDN noise if possible)
  </action>
  <verify>
    Run npm run build && npm run smoke:tools
    Check extension loads without permission errors
    Manual test: Navigate to a page, run browser_network_requests tool, verify requests are captured
  </verify>
  <done>
    - manifest.json includes "webRequest" permission
    - background.js has sessionNetworkLogs Map with ring buffer
    - webRequest listeners registered with tabId filter
    - handleGetNetworkRequests command returns filtered request data
    - Logs clear automatically on session loss (verify by checking logs after tab close)
  </done>
</task>

<task type="auto">
  <name>Task 2: Implement console message capture via content script</name>
  <files>
    extension/content-script.js
    extension/background.js
  </files>
  <action>
    Implement console capture in content-script.js:
    1. Create bounded ring buffer for console logs (max 1000 entries)
    2. Override console.log, console.error, console.warn, console.info:
       - Push to buffer with: level, message, timestamp, stack trace
       - Call original method to preserve page functionality
       - Preserve original method descriptors to avoid breaking page functionality
    3. Add window.onerror listener for uncaught exceptions
    4. Expose getConsoleLogs() function that returns and optionally clears buffer
    5. Listen for "getConsoleLogs" message from background script

    Update background.js:
    1. Add handleGetConsoleMessages command
    2. Send message to content script to retrieve logs
    3. Format response with level filtering support
    4. Clear console logs on session loss (tab close, transport drop)

    PITFALLS TO AVOID:
    - MUST preserve original console descriptors (some sites check toString())
    - MUST use .apply() to maintain correct 'this' context
    - MUST bound buffer size to prevent memory exhaustion
    - MUST handle case where content script not yet injected
  </action>
  <verify>
    Run npm run build
    Manual test: Navigate to page with console output, run browser_console_messages, verify logs captured
    Verify buffer bounds by checking logs don't exceed 1000 entries
  </verify>
  <done>
    - content-script.js overrides console methods with ring buffer
    - window.onerror captures uncaught exceptions
    - background.js has handleGetConsoleMessages command
    - Logs return with level, message, timestamp, stack
    - Buffer size bounded to 1000 entries
  </done>
</task>
