  <action>
    Fix the timeout comparison for text-waiting modes to convert seconds to milliseconds in handleWaitFor (added by 03-06):
    
    Note: This implements the unit conversion logic within handleWaitFor that 03-06 left as TODO.

    1. In extension/content-script.js, find handleWaitFor function (added by 03-06 around line 529):
       Look for the TODO comment indicating unit conversion will be added in 03-07.

    2. The issue: timeout comes in as seconds (e.g., 10), but Date.now() - startTime gives milliseconds.
       Comparison `elapsed >= timeout` compares ms against seconds, causing immediate timeout.

    3. Add timeout conversion at the start of handleWaitFor:
       ```javascript
       async function handleWaitFor(params) {
         const { mode, value, timeout: timeoutSeconds = 30 } = params;
         // Convert timeout from seconds (API) to milliseconds (for comparison with Date.now)
         const timeoutMs = timeoutSeconds * 1000;
         const startTime = Date.now();
       ```

    4. Update mode=text block to use timeoutMs:
       Replace the TODO comment and `while (Date.now() - startTime < timeout)` with:
       ```javascript
       if (mode === 'text') {
         while (Date.now() - startTime < timeoutMs) {
           if (document.body.innerText.includes(value)) {
             return { success: true };
           }
           await new Promise(resolve => setTimeout(resolve, 100));
         }
         throw new Error(`Timeout waiting for text: "${value}"`);
       }
       ```

    5. Update mode=text_gone block similarly:
       ```javascript
       if (mode === 'text_gone') {
         while (Date.now() - startTime < timeoutMs) {
           if (!document.body.innerText.includes(value)) {
             return { success: true };
           }
           await new Promise(resolve => setTimeout(resolve, 100));
         }
         throw new Error(`Timeout waiting for text to disappear: "${value}"`);
       }
       ```

    6. Build and load extension: `npm run build` and reload in Firefox
  </action>
